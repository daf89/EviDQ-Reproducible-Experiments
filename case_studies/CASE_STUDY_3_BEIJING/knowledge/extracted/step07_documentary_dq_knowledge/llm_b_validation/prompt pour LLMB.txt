============================================================
MISSION
============================================================

Votre mission n'est PAS de refaire l'extraction documentaire.

Votre mission est exclusivement de :

VALIDER INDÉPENDAMMENT CHAQUE CONNAISSANCE K001–K011
CONTRE LES DOCUMENTS PDF ORIGINAUX.

Vous devez déterminer si chaque affirmation de LLM-A est réellement supportée
par le document cité.

LLM-A peut avoir :

- correctement extrait une connaissance ;
- légèrement surinterprété un passage ;
- attribué un mauvais niveau d'applicabilité ;
- transformé une recommandation qualitative en règle exécutable ;
- généralisé un exemple particulier ;
- attribué une connaissance à la mauvaise feature ;
- mal indiqué la page ou la section ;
- inventé implicitement une expression opérationnelle ;
- proposé une action plus forte que ce que permet la source.

Vous devez détecter ces problèmes.

LLM-B n'est pas non plus une source de connaissance.

============================================================
PRINCIPES ÉPISTÉMIQUES OBLIGATOIRES
============================================================

Respecter strictement :

Observation ≠ Anomalie

Anomalie ≠ Erreur

Outlier statistique ≠ valeur erronée

Valeur extrême ≠ valeur invalide

Valeur manquante ≠ erreur

Valeur manquante ≠ obligation d'imputation

Dépassement environnemental/réglementaire
≠ erreur de qualité des données

Flag ≠ invalidation

Review ≠ correction

Possibilité de récupérer une donnée
≠ autorisation d'imputer une donnée

Documentation EPA
≠ protocole réellement utilisé pour le dataset Beijing.

Une règle nécessitant un instrument particulier ne peut être considérée
DIRECT si l'instrument utilisé à Beijing n'est pas connu.

============================================================
VALIDATION À EFFECTUER POUR CHAQUE K
============================================================

Pour chacune des connaissances K001 à K011, effectuer les contrôles suivants.

------------------------------------------------------------
A. EXISTENCE
------------------------------------------------------------

Le passage documentaire existe-t-il réellement dans le PDF indiqué ?

Répondre :

YES
PARTIAL
NO

------------------------------------------------------------
B. SOURCE
------------------------------------------------------------

Vérifier :

- document_id ;
- titre du document ;
- organisation ;
- année ;
- section ;
- page.

Corriger les informations erronées ou imprécises lorsque le PDF permet de
le faire.

------------------------------------------------------------
C. FIDÉLITÉ DE evidence_text
------------------------------------------------------------

Vérifier que evidence_text représente réellement le passage source.

Ne pas exiger que ce soit une citation longue.

Mais vérifier que LLM-A n'a pas fabriqué une formulation qui modifie le sens
du document.

------------------------------------------------------------
D. FEATURE APPLICABILITY
------------------------------------------------------------

Le passage s'applique-t-il réellement à la feature indiquée ?

Exemple :

une recommandation générique sur les données atmosphériques ne devient pas
automatiquement une règle spécifique PM2.5.

Distinguer :

DIRECT
CONDITIONAL
DIAGNOSTIC_ONLY
NOT_APPLICABLE

------------------------------------------------------------
E. DQ PROBLEM APPLICABILITY
------------------------------------------------------------

Le passage concerne-t-il réellement :

MISSING_VALUE

ou

POTENTIAL_OUTLIER

tel qu'indiqué par LLM-A ?

------------------------------------------------------------
F. CRITERION_DESCRIPTION
------------------------------------------------------------

La description du critère est-elle fidèle au document ?

Vérifier particulièrement si LLM-A a transformé :

- un exemple en règle générale ;
- une recommandation en obligation ;
- une possibilité en critère ;
- une observation en diagnostic ;
- un screening en règle d'invalidation.

------------------------------------------------------------
G. CRITERION_EXPRESSION
------------------------------------------------------------

C'est un contrôle CRITIQUE.

Pour chaque expression telle que :

PM10 >= PM2.5

DEWP <= TEMP

PM2.5 IS MISSING

REPEATED_IDENTICAL_VALUES -> FLAG

déterminer si cette expression est réellement supportée par le document.

Attribuer :

EXPLICITLY_SUPPORTED
FAITHFUL_FORMALIZATION
OVER_FORMALIZED
NOT_SUPPORTED

Définitions :

EXPLICITLY_SUPPORTED =
le document donne explicitement la relation ou son équivalent direct.

FAITHFUL_FORMALIZATION =
le document donne clairement la règle en langage naturel et sa formalisation
ne change pas son sens.

OVER_FORMALIZED =
le document donne une idée qualitative mais LLM-A l'a transformée en règle
opérationnelle trop forte.

NOT_SUPPORTED =
la règle ne peut pas être dérivée du document.

------------------------------------------------------------
H. CONTROL_FEATURES
------------------------------------------------------------

Vérifier que les variables auxiliaires indiquées sont réellement nécessaires
et justifiées par la connaissance documentaire.

------------------------------------------------------------
I. OPERATIONAL STATUS
------------------------------------------------------------

Vérifier si :

EXECUTABLE

REQUIRES_ADDITIONAL_INFORMATION

DIAGNOSTIC_ONLY

NO_SUPPORTED_RULE

est correctement attribué.

Une connaissance qualitative sans seuil opérationnel ne doit pas être
déclarée EXECUTABLE si son exécution nécessite d'inventer le seuil.

------------------------------------------------------------
J. CANDIDATE ACTION
------------------------------------------------------------

Vérifier particulièrement :

KEEP
FLAG
REVIEW
RECOVER
CORRECT
IMPUTE
EXCLUDE
INVALIDATE
ABSTAIN
NONE

L'action doit être réellement supportée par la source.

Ne jamais accepter :

missing → IMPUTE

ou :

outlier → INVALIDATE/EXCLUDE

sans support documentaire explicite.

------------------------------------------------------------
K. INFORMATION MANQUANTE
------------------------------------------------------------

Déterminer si l'application nécessite des informations non disponibles dans
le dataset, par exemple :

- instrument ;
- modèle du capteur ;
- plage instrumentale ;
- calibration ;
- QA/QC logs ;
- maintenance logs ;
- SOP ;
- QAPP ;
- station externe ;
- historique supplémentaire ;
- seuil spécifique au site.

Effectuer une vérification particulièrement stricte des éléments suivants :

1. La règle proposée :

DEWP <= TEMP

Est-elle réellement formulée comme principe physique dans le document

2. La règle proposée :

Le document la présente-t-il comme :

- une relation physique générale ;
- un contrôle de cohérence ;

Ne pas accepter automatiquement sa classification PHYSICAL/DIRECT.

Le document permet-il de détecter directement une anomalie sans préciser

Si aucun seuil de durée/nombre de répétitions n'est donné, déterminer ce qui
est réellement exécutable sans inventer un seuil.

4. WSPM et rate-of-change.

seuil applicable au cas Beijing, ne pas considérer automatiquement la règle
comme exécutable.

5. WSPM et plages instrumentales.

Vérifier que cette connaissance reste CONDITIONAL si le type d'instrument
Beijing n'est pas connu.

6. Missing values.

Vérifier qu'aucune des connaissances K001-K005 ne transforme :

détection du gap + recherche de cause

en :

imputation automatique.
