Je travaille sur une étude scientifique intitulée DEMARCHE_ENCAD3.

CONTEXTE

L'objectif général de DEMARCHE_ENCAD3 est d'étudier si une gestion des problèmes de qualité des données guidée par des connaissances documentaires peut fournir une alternative explicable, traçable et contrôlée à une correction statistique directe des données.

Dans cette étude de cas, le dataset est le Beijing Multi-Site Air Quality Data Set.

Une étape antérieure, indépendante de cette tâche, a déjà construit un modèle de référence et réalisé une analyse SHAP sur l'ensemble de VALIDATION.

Les variables mesurées importantes qui ont été retenues sont :

- PM2.5
- PM10
- WSPM
- DEWP
- CO

Cette sélection est FIXÉE. Vous ne devez pas la recalculer ni la remettre en question.

Deux problèmes de qualité des données doivent maintenant être étudiés :

1. MISSING_VALUE
2. POTENTIAL_OUTLIER

Les sources de connaissance sont exclusivement les documents officiels fournis.

Votre rôle consiste uniquement à :

- lire ;

- extraire ;
- structurer ;
- comparer ;
- relier les connaissances documentaires aux features et aux problèmes DQ.


============================================================
PRINCIPES ÉPISTÉMIQUES OBLIGATOIRES
============================================================

Vous devez impérativement respecter les distinctions suivantes :

Observation ≠ Anomalie

Anomalie ≠ Erreur

Outlier statistique ≠ valeur erronée

Valeur extrême ≠ valeur invalide

Valeur manquante ≠ panne du capteur

Valeur manquante ≠ obligation d'imputation

Dépassement d'un seuil environnemental ou réglementaire
≠ erreur de qualité des données

Amélioration de la prédiction
≠ amélioration de la qualité des données

Une recommandation EPA
≠ preuve que le dataset Beijing a été collecté selon cette procédure.

Les documents EPA doivent être utilisés comme SOURCE EXTERNE INDÉPENDANTE DE CONNAISSANCE.

Ne jamais affirmer que les procédures EPA ont été appliquées au dataset Beijing.

RÈGLES D'EXTRACTION
============================================================

Pour chaque connaissance pertinente trouvée, extraire :

1. feature

2. dq_problem :
   - MISSING_VALUE
   - POTENTIAL_OUTLIER

3. knowledge_type :
   - SEMANTIC
   - PHYSICAL
   - INSTRUMENT
   - QA_QC
   - STATISTICAL_DOCUMENTED
   - TEMPORAL
   - SPATIAL
   - COMPLETENESS
   - VALIDATION

4. criterion_description

5. criterion_expression

Si le document permet une expression opérationnelle, l'écrire.

Exemple uniquement si documenté :

DEWP <= TEMP

Sinon écrire :

NOT_EXPLICITLY_SPECIFIED

Ne jamais inventer une formule ou un seuil.

6. control_features

Variables supplémentaires nécessaires pour appliquer le critère.

7. document

Nom exact du PDF source.

8. document_title

9. organization

10. publication_year

11. source_section

Section exacte lorsque identifiable.

12. source_page

Page du document lorsque identifiable.

13. evidence_text

Donner un extrait MINIMAL du passage réellement nécessaire pour justifier l'extraction.

Ne pas recopier de longues sections du document.

14. documentary_interpretation

Expliquer précisément ce que le passage permet de conclure.

15. applicability :

DIRECT
CONDITIONAL
DIAGNOSTIC_ONLY
NOT_APPLICABLE

Définitions :

DIRECT =
la connaissance est explicitement documentée et peut être testée avec les variables disponibles dans le dataset.

CONDITIONAL =
la connaissance est documentée mais nécessite une information supplémentaire que nous ne possédons pas nécessairement, par exemple spécification de l'instrument, calibration, logbook, maintenance ou documentation QA/QC.

DIAGNOSTIC_ONLY =
la connaissance aide à investiguer ou interpréter le problème mais ne suffit pas à déterminer directement la validité de la valeur.

NOT_APPLICABLE =
la connaissance existe mais son champ d'application ne permet pas de l'utiliser pour cette feature/dataset sans hypothèse injustifiée.

16. applicability_reason

17. operational_status :

EXECUTABLE
REQUIRES_ADDITIONAL_INFORMATION
DIAGNOSTIC_ONLY
NO_SUPPORTED_RULE

18. candidate_action

Utiliser uniquement :

KEEP
FLAG
REVIEW
RECOVER
CORRECT
IMPUTE
EXCLUDE
INVALIDATE
ABSTAIN
NONE

IMPORTANT :

Une action ne doit être indiquée que si le document la supporte réellement.

Ne jamais transformer automatiquement :

MISSING_VALUE → IMPUTE

ou

POTENTIAL_OUTLIER → EXCLUDE/CORRECT.

19. action_conditions

Préciser les conditions documentaires nécessaires pour autoriser l'action.

20. missing_information

Préciser les informations nécessaires mais absentes du dataset si applicable.

21. limitations

22. epistemic_status

Utiliser une formulation explicite parmi :

DOCUMENTED_DIRECT_KNOWLEDGE
DOCUMENTED_CONDITIONAL_KNOWLEDGE
DOCUMENTED_DIAGNOSTIC_KNOWLEDGE
INSUFFICIENT_DOCUMENTARY_EVIDENCE


============================================================
RÈGLES SPÉCIALES POUR LES MISSING VALUES
============================================================

Ne jamais supposer qu'une valeur manquante doit être imputée.

Chercher séparément si les documents supportent :

- identification du gap ;
- recherche de la cause ;
- récupération de la mesure originale ;
- qualification/codage de la valeur absente ;
- utilisation d'informations auxiliaires ;
- remplacement ;
- interpolation ;
- imputation ;
- exclusion ;
- abstention.

Si aucune méthode de remplacement n'est explicitement supportée :

NE PAS INVENTER D'IMPUTATION.

La conclusion peut parfaitement être :

ABSTAIN.


============================================================
RÈGLES SPÉCIALES POUR LES POTENTIAL OUTLIERS
============================================================

Un outlier détecté statistiquement est uniquement :

POTENTIAL_OUTLIER

Il ne devient jamais automatiquement une erreur.

Chercher si les documents proposent des preuves permettant de distinguer :

REAL_EXTREME_VALUE

SUSPECT_VALUE

INVALID_VALUE

INSTRUMENT_PROBLEM

INSUFFICIENT_EVIDENCE

Chercher notamment les connaissances documentées permettant de confronter une valeur suspecte avec :

- historique ;
- station proche ;
- autres variables ;
- comportement physique ;
- QA/QC ;
- calibration ;
- fonctionnement du capteur ;
- répétition/stuck values ;
- variation temporelle.

Si les preuves sont insuffisantes :

ABSTAIN ou REVIEW,

selon ce que supporte réellement le document.

INTERDICTIONS
============================================================

Il est strictement interdit de :

- fabriquer une plage de validité ;
- inventer un seuil ;
- inventer une règle métier ;
- inventer une procédure EPA ;
- utiliser votre connaissance générale pour compléter un PDF ;
- transformer un standard environnemental en limite de validité des données ;

- supposer le type d'instrument utilisé à Beijing ;
- supposer que les procédures EPA ont été appliquées à Beijing ;
- recommander une imputation simplement parce qu'une valeur est manquante ;
- recommander une suppression simplement parce qu'une valeur est statistiquement atypique ;
- sélectionner une action sur la base des performances du modèle prédictif.
